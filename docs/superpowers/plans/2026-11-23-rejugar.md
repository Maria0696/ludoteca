# Rejugar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que un juego ya superado se pueda rejugar sin perder lo superado: vueltas con inicio y fin, «Vuelta N» en la ficha y cada vuelta terminada contada en Estadísticas.

**Architecture:** El juego guarda sus vueltas anteriores cerradas en `pastRuns`; la vuelta en curso sigue siendo `startedAt`/`finishedAt`, así casi nada que ya lee esas fechas cambia. Las reglas viven en un módulo puro (`src/lib/runs.ts`) que usan el store, Estadísticas, el mapa y la ficha.

**Tech Stack:** Next.js 16 (App Router), TypeScript, zod, Supabase, IndexedDB (modo local), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-23-rejugar-design.md`

## Global Constraints

- Todo en español de España; «Vuelta 2», nunca «2.ª vuelta» (en Press Start 2P la «ª» se confunde).
- Nada que escribir: solo botones y fechas automáticas.
- Supabase: columna `past_runs jsonb not null default '[]'` en `public.games` (migración `0010_vueltas.sql`). **No se aplica sin permiso explícito de la propietaria.**
- La copia de seguridad no cambia de versión (`BACKUP_VERSION = 1`): `pastRuns` tiene valor por defecto `[]`.
- Los juegos sin final (`endless`) no tienen «Rejugar».
- TDD: cada prueba se ve fallar antes del código. En local solo los specs afectados.
- No pasar prettier por archivos enteros.

## Review Focus

1. Pasar a mano de «Completado» a «Pausado» o «Abandonado» no archiva la vuelta (la spec solo nombra Jugando/Pendiente): el juego sigue con su `finishedAt` y cuenta como superado. → prueba en Task 2.
2. «Deshacer» tras «Rejugar» o tras un cambio de estado que archivó una vuelta devuelve también `pastRuns`. → prueba en Task 2.
3. Borrar la fecha de «Termina la historia» en la vuelta 2 no toca las vueltas anteriores. → prueba en Task 2.
4. Una copia de seguridad antigua (sin `pastRuns`) se sigue importando. → prueba en Task 1.
5. «El último» de Estadísticas, con una vuelta terminada hoy de un juego superado hace meses, nombra ese juego con la fecha de hoy. → prueba en Task 3.

**Interfaces:**
- Produces:
  - `gameSchema.pastRuns: z.array(z.object({ start: isoDate.nullable(), end: isoDate })).default([])` → `Game["pastRuns"]: { start: string | null; end: string }[]`
  - `runs.ts`: `type Run = Game["pastRuns"][number]`
  - `runNumber(game: Game): number` → `pastRuns.length + 1`
  - `timesFinished(game: Game): number` → `pastRuns.length + (finishedAt ? 1 : 0)`
  - `finishDates(game: Game): string[]` → `end` de cada vuelta anterior + `finishedAt` si lo hay
  - `archiveRun(game: Game): Game` → si hay `finishedAt`, añade `{ start: startedAt ?? null, end: finishedAt }` a `pastRuns` y deja `startedAt`/`finishedAt` en `null`; si no, devuelve el juego igual
  - `reopenSameDayRun(game: Game, today: string): Game | null` → si la última vuelta anterior acaba `today`, el juego no tiene `finishedAt` y `startedAt` es `today` o `null`, la saca de `pastRuns` y la devuelve como vuelta en curso (`startedAt = run.start`, `finishedAt = run.end`); si no, `null`
